# Map Tunisia — Specification

## Data sources
- **Boundaries:** OpenStreetMap via the Geofabrik `tunisia-latest.osm.pbf` extract (date recorded per build). Relations used: `boundary=administrative` with admin_level 4 (governorates), 5 (delegations) and 6 (sectors/imadas), plus `natural=coastline` ways (for islets not covered by the governorate relations).
- **Codes:** OSM tags `ISO3166-2`, `ref:tn:codegeo` (INS geocode), `ref:tn:hasc_2`, `wikidata`.
- **Groupings:**
  - The 7 economic regions follow the INS/ISO grouping: Grand Tunis TN-1x, Nord-Est TN-2x, Nord-Ouest TN-3x, Centre-Ouest TN-4x, Centre-Est TN-5x + TN-61, Sud-Ouest TN-7x, Sud-Est TN-8x.
  - The 5 districts follow Decree 2023-589 of 21 September 2023.
- **Delegations created after 2014** are rebuilt from their member imadas wherever an open source documents the composition. Otherwise they are listed as a known limitation.
- **Attributes:** 2024 census population (INS RGPH 2024) where available.

## Processing (scripts/extract, Python)
1. Read the PBF with pyosmium and assemble the multipolygons.
2. Build a planar face set by noding together all governorate, delegation and sector boundaries and the islets.
3. Assign each face to a governorate, a delegation and a sector, using containment and documented conflict rules (superseded relations dropped, overlaps resolved).
4. Split gaps (inland lakes and sebkhas that the lower levels leave out) among the neighbouring units within the same parent, by nearest-boundary (Voronoi) allocation.
5. Dissolve the faces into exactly nested units. Write `data/source/tunisia-sectors.geojson` (WGS84, full precision) and attribute tables.

## Generation (scripts/build, Node.js)
- mapshaper performs topology-aware simplification. Per partition, the layer is dissolved at full precision, projected to UTM zone 32N (EPSG:32632), then simplified at each level of detail:
  - full: no simplification
  - high: about 20 m
  - medium: about 100 m
  - low: about 500 m
  - tiny: about 2.5 km
- A custom SVG writer emits semantic markup: `<g id="governorates">`, `<path id="TN-11" data-name-fr= data-name-ar= ...>`, `<title>`, a metadata block holding the projection and transform, and `viewBox` scaling.
- Labels are placed at the pole of inaccessibility (polylabel).
- Outputs:
  - `dist/svg/<partition>/tunisia-<partition>-<lod>-<mode>.svg`
  - `dist/geojson/` and `dist/topojson/` in WGS84
  - `dist/data/*.csv|json`
  - `dist/manifest.json`

## Interfaces
- **File naming:** `tunisia-<partition>-<lod>-<mode>.svg`.
- **Feature IDs:**
  - country: `TN`
  - regions and districts: slugs
  - governorates: ISO 3166-2 code (`TN-11`)
  - delegations and sectors: INS geocodes prefixed per level (`TN-D-1157`, `TN-S-115751`), with a deterministic fallback when a unit has no code
- **JS helper:** `project(lon, lat) -> [x, y]` in SVG user units.

## Quality
Automated tests (`npm test`) check:
- counts per partition
- unique IDs
- well-formed XML in every SVG
- exact nesting (each unit's parent exists and the unit lies inside it)
- no gaps or overlaps in the source data beyond tolerance
- the area of each governorate compared with the full-precision data
- size budgets per level of detail

GitHub Actions CI runs the tests. An accuracy report (`docs/accuracy.md`) is generated by the build.

## Known limitations (tracked)
- OSM sector (imada) boundaries reflect the INS 2014 structure.
- Inland water allocation between delegations is approximate.
