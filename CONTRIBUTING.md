# Contributing to Map Tunisia

Thank you for helping make the best map of Tunisia even better. Contributions of every size are welcome:
a misspelled name, a wrong border, a new mode, better docs or a translation.

- [Report a data error](#report-a-data-error)
- [Project layout](#project-layout)
- [Set up](#set-up)
- [Change the maps](#change-the-maps)

## Report a data error

Open a **[data error issue](https://github.com/Alaa-Taieb/map-tunisia/issues/new?template=data-error.yml)** and tell us:

- which unit is wrong. Its `id` (e.g. `delegation-3362` or `TN-53`) is shown in the [explorer](https://alaa-taieb.github.io/map-tunisia/) when you click a shape;
- what is wrong: name, border, code, parent or population;
- a source: a decree in the JORT, an INS publication, an ISIE map, or local knowledge.

Borders come from OpenStreetMap, so the best fix is often **upstream**. Correct the boundary in
[OpenStreetMap](https://www.openstreetmap.org) (see the [Tunisia wiki page](https://wiki.openstreetmap.org/wiki/Tunisia)),
and we pick it up at the next data refresh. Fixes that can't wait, or that OSM does not model, go into
[`scripts/extract/corrections.json`](scripts/extract/corrections.json) with a `reason` and a source.

## Project layout

```text
data/
  source/tunisia-sectors.geojson   nested master layer (WGS84, full precision), generated by extract.py
  source/extract-report.json       statistics, corrections and warnings from the last extraction
  source/tunisia-municipalities.geojson  municipalities, a separate non-nested layer, generated by municipalities.py
  source/tunisia-water.geojson     water bodies (lakes, dams, sebkhas, chotts, lagoons), an overlay, generated by water.py
  attributes/*.csv                 names, codes, hierarchy and populations (governorates, regions and districts are hand-curated)
  reference/                       independent figures, used only to check the maps
scripts/
  extract/                         Python: OSM extract → clean, nested source data
    fetch.py                       downloads the Geofabrik extract into .cache/
    extract.py                     builds the planar topology and nests every level
    municipalities.py              municipalities (boundary=municipality) clipped to the land, overlaps resolved
    water.py                       named lakes, dams, sebkhas and chotts, plus the sea-side lagoons cut from the coastline
    corrections.json               every documented correction to OSM, with reasons and sources
  build/                           Node: source data → dist/
    config.js                      the partitions × levels of detail × modes matrix
    build.js                       dissolve, project, simplify, label; writes SVG, GeoJSON and TopoJSON
    svg.js                         the SVG writer and the CSS of each mode
    showcase.js                    README illustrations in docs/assets/
    report.js                      docs/accuracy.md and docs/catalog.md
src/                               the tiny JS API (paths, CDN URLs, projection)
site/                              the interactive explorer (GitHub Pages)
dist/                              generated maps. Never edit by hand
docs/                              documentation
test/                              node:test suite
```

## Set up

You need **Node.js 20+**. Python is only needed to refresh the data from OpenStreetMap.

```bash
git clone https://github.com/Alaa-Taieb/map-tunisia.git
cd map-tunisia
npm install
npm run build      # regenerate dist/ from data/ (about 30 s)
npm test           # validate everything
```

To refresh from OpenStreetMap (Python 3.10+):

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r scripts/extract/requirements.txt
npm run fetch                    # download the latest Geofabrik extract (~85 MB) into .cache/
npm run extract                  # rebuild data/source and data/attributes (~40 s)
npm run build && npm test
```

## Change the maps

| I want to… | Edit |
| --- | --- |
| fix a governorate, region or district name | `data/attributes/governorates.csv`, `regions.csv`, `districts.csv` |
| fix a delegation or sector name | `names` in `scripts/extract/corrections.json` (or fix it in OSM) |
| move a sector to another delegation | `sector_reassignments` in `scripts/extract/corrections.json` |
| add a new delegation | `new_delegations` in `scripts/extract/corrections.json` |
| change the colours, strokes or fonts of a mode | `css()` in `scripts/build/svg.js` and `PALETTES` in `config.js` |
| add a mode, level of detail or partition | `scripts/build/config.js` |

Then run `npm run build && npm test`. Commit the regenerated `dist/`, `src/catalog.js` and `docs/` files with
your change, so users can download maps straight from the repository.

## Pull requests

1. Fork the repository and create a branch (`fix/kebili-sector-codes`, `feat/hillshade-mode`…).
2. Keep each pull request to one change.
3. Run `npm test`. CI runs the same checks.
4. Explain *why*. For data changes, link the source.
5. By contributing, you agree that your code is released under the MIT licence and your data changes under the
   ODbL 1.0, like the rest of the project.

Please follow the [Code of Conduct](CODE_OF_CONDUCT.md). Thank you!
